# 测试指南

> 跑测试前的两个事实：**必须在仓库根目录跑**；测试**永远不会碰你的真实配置**（有沙箱和绊线）。

## 1. 怎么跑

```bash
uv run pytest -q                       # 全量（约 700+，1–2 分钟）
uv run pytest tests/test_router.py -v  # 单文件
uv run pytest -k "stream and cache"    # 按名字过滤
```

E2E（需要真实代理在跑）：

```bash
RUN_E2E_TESTS=1 TEST_BASE_URL=http://127.0.0.1:18401 TEST_API_KEY=local \
  uv run pytest tests/test_e2e_multimodel.py -v
```

> `tests/test_integration.py` 目前有一个**无条件 skip**，设 `RUN_INTEGRATION_TESTS=1` 也不会执行（见开发指南 §6）。
> `tests/integration/` 是普通套件的一部分，用 ASGITransport + mock 上游，不会联网。

## 2. 沙箱是怎么工作的（不要绕开它）

`tests/conftest.py`：

| 机制 | 作用 | 为什么必须这样 |
|---|---|---|
| **模块级** 设置 `CCCONVERT_CONFIG_DIR` / `CCCONVERT_RUNTIME_DIR` | 所有测试写入临时目录 | `daemon.py` 在**导入时**就把路径固化成模块级常量，fixture 阶段已经太晚 |
| 真实配置绊线 | 会话前后比对 `~/.ccconvert/config.toml` 的 mtime/size | 曾经有测试把用户真实配置原子覆盖 |
| 每个用例重置环境变量 | 防止 `patch.dict(clear=True)` 把沙箱变量清掉 | 清掉后代码会回落真实目录 |
| autouse patch `check_upstream_base_url` | 保存时的可达性探测会真的发网络请求 | 不让单测联网 |
| autouse 关闭日志文件句柄 | `setup_logging` 的 FileHandler 长期占用文件 | Windows 上不关掉，`TemporaryDirectory` 清理会 `WinError 32` |
| 收集数量下限 500 | 防止某个模块导入失败、整文件测试静默消失 | 只对全量运行生效 |

**规则：不要创建第二种沙箱方式**；需要特殊路径就用 `monkeypatch.setenv` 并在用例内改回。

> **usage.db 的特殊性**：许多路由级测试会通过 `create_app` 触发用量采集并**持有**共享沙箱
> `usage.db` 的连接（Windows 上无法 unlink），而且会往里写数据。涉及 usage 断言的测试
> （`tests/test_usage_api.py`）必须用 `monkeypatch.setenv("CCCONVERT_RUNTIME_DIR", tmp)`
> 指到私有目录，不能直接用共享沙箱库。

## 3. 测试分层

| 层 | 位置 | 特征 |
|---|---|---|
| 单元 | `test_converter*.py`、`test_protocol.py`、`test_cache_usage.py` 等 | 纯函数，无网络 |
| 用量 | `tests/usage/`（recording/ledger/store/集成）、`test_usage_api.py` | 纯函数 + 假上游 + tmp SQLite |
| 路由 | `test_router*.py`、`test_responses_api.py`、`test_passthrough.py` | `TestClient` + mock httpx |
| Manager | `test_manager_routes.py`、`test_daemon*.py`、`test_port_health.py` | mock store/supervisor、patch subprocess |
| 进程内集成 | `tests/integration/` | ASGI + 假上游，普通套件 |
| E2E | `test_e2e_*.py`、`test_integration.py` | 环境变量门控，需真实服务 |
| 手动 | `tests/test_upstream.sh` | curl 矩阵，非 pytest |

## 4. 常见写法

### 4.1 Mock 上游 HTTP

```python
with patch("cc_convert.router.httpx.AsyncClient") as mock_cls:
    client = AsyncMock()
    client.post.return_value = httpx.Response(200, json={...}, request=httpx.Request("POST", url))
    mock_cls.return_value.__aenter__.return_value = client
```

三种常见变体（都已在用）：

- patch 类，返回 `AsyncMock` 客户端；
- patch `httpx.AsyncClient.post`，返回真实 `httpx.Response`；
- 子类化 `httpx.AsyncClient` 捕获请求体做断言。

**注意**：`_stream_response` 走 `client.stream(...)`（异步上下文管理器），要 mock `__aenter__` 返回带 `aiter_lines()` 的对象。

### 4.2 流式 SSE

```python
async def aiter_lines():
    for line in ['data: {"choices":[...]}', "data: [DONE]"]:
        yield line
response.aiter_lines = aiter_lines
```

断言输出里包含 `event: message_start` / `content_block_delta` / `message_stop`。

### 4.3 Manager 路由

```python
client = TestClient(app, headers={"Host": "localhost"})   # 主机校验
client.post("/api/instances", json=..., headers={"X-CCCONVERT-CSRF": app.state.csrf_token})
```

Supervisor 的异步方法用 `AsyncMock`；store 用真实 `ProfileStore` 或内存假对象。

### 4.4 子进程 / 守护进程

- `daemon` 的路径常量在导入时绑定，测试里要 `monkeypatch.setattr(daemon, "MANAGER_PID_FILE", tmp)`。
- 杀进程必须 patch `subprocess.run` 并断言参数（Windows 断言 `/F /T`）。
- POSIX-only 用 `pytest.mark.skipif(sys.platform == "win32")`。

## 5. 写新测试的检查清单

1. 是否依赖真实网络？→ 必须 mock。
2. 是否读写真实目录？→ 用 `tmp_path`，不要用 `Path.home()`。
3. 是否调用 `subprocess`？→ patch 掉。
4. 是否启动线程/后台任务？→ 结束时确保能退出（daemon 线程或显式 stop）。
5. 是否改环境变量？→ 用 `monkeypatch.setenv`（自动恢复）。
6. 是否断言 usage/token？→ 用 `extract_cache_read_tokens` / `anthropic_input_tokens` / `usage.recording.normalize_usage` 的口径验证，不要手写一个近似值。
7. 是否触到用量采集？→ 断言台账/库里的 `unreported`、`requests` 语义（错误请求也是请求），参考 `tests/usage/test_integration_collection.py`。

## 6. 常见失败与原因

| 现象 | 原因 |
|---|---|
| 收集阶段就报 ImportError | 有模块在导入时崩了；`test_smoke_imports.py` 会指出是哪个 |
| Windows 上 `PermissionError` 删目录 | 日志 FileHandler 没关；用 `tests/logging_support.close_file_handlers()` |
| 本地全绿、CI 红 | 多半是平台差异（路径、`taskkill`、SIGKILL、socket 表） |
| 测试跑完真实配置被改 | 沙箱被绕开；检查是否用了 `clear=True` 或直接构造了 ambient 路径 |
| 异步测试没执行 | 缺 `@pytest.mark.asyncio`（`asyncio_mode=strict`，不会自动收集） |
