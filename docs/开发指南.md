# 开发指南

> 面向要改代码的人（或 agent）。先读 [架构总览](架构总览.md) 和 [不变量与陷阱](不变量与陷阱.md)，再动手。

## 1. 环境

- Python **3.12**（`requires-python` 下限）
- 包管理用 **uv**（`uv.lock` 已提交）
- Windows / macOS / Linux 都要能跑；Windows 是主要使用场景

```bash
git clone <repo>
cd <repo 根目录>
uv sync                 # 装运行时 + dev 依赖（dependency-groups）
uv run pytest -q        # 必须在仓库根目录跑
uv run ccconvert start  # 启动 Manager
```

> `uv sync --locked` 会在 `pyproject.toml` 与 `uv.lock` 不一致时失败——CI 用的就是它。

## 2. 命令速查

| 目的 | 命令 |
|---|---|
| 同步依赖 | `uv sync` |
| 跑全部测试 | `uv run pytest -q` |
| 跑单个文件 | `uv run pytest tests/test_router.py -v` |
| 只跑慢/集成 | 见 [测试指南](测试指南.md) |
| Lint | `uv run ruff check src tests` |
| 格式化 | `uv run black src tests`（CI 未强制） |
| 类型检查 | `uv run mypy src`（CI 未强制，但 `strict = true`） |
| 启动面板 | `uv run ccconvert start` / `open` / `status` |
| 看日志 | `uv run ccconvert logs -f` |
| 打包 exe | `uv sync --group build` → `uv run pyinstaller ccconvert.spec --noconfirm --clean` |
| 发布 | 改版本号 → 测试 → 提交 → `git tag vX.Y.Z && git push origin vX.Y.Z` |

## 3. 改动配方

### 3.1 给实例加一个配置项

按顺序改，漏一步就会出现「面板能填但 Worker 收不到」或反之：

1. `profile_store.InstanceProfile` 加字段（给默认值，保证老配置可加载）。
2. `build_worker_settings()` 把它放进 settings 快照。
3. `config.Settings` 加同名字段（Worker 侧读取）。
4. `web/routes.py`：`create_instance` / `update_instance` 接收并校验；`_instance_to_response` 返回。
5. `templates/config.html` 加表单控件与回显。
6. 测试：创建/更新/回显各一条；老配置缺字段时用默认值。

> schema 变更必须幂等（见不变量 D3）。

### 3.2 加一个 Dashboard API

1. `web/routes.py` 加 `@web_router.<method>`；变更类请求会被 CSRF 中间件校验。
2. 返回结构尽量与现有实例接口保持一致（前端已有一套渲染约定）。
3. 会阻塞的同步操作（shell、文件遍历、网络探测）用 `await asyncio.to_thread(...)`。
4. 测试放 `tests/test_manager_routes.py`，用 `TestClient(app, headers={"Host": "localhost"})` + `app.state.csrf_token`。

### 3.3 加/改协议字段（热路径）

1. 先确认三条入口 × 流式/非流式的影响矩阵（见架构总览 §3）。
2. 改 `converter.py` 的对应转换；流式字段在 `streaming/handler.py`。
3. 上游若是 Responses，还要看 `upstream_responses.py`。
4. 补测试：`test_converter*.py`、`test_router_streaming.py`、`test_upstream_responses.py`。
5. 跑全量测试——这里的回归通常不会在局部测试里暴露。

### 3.4 加一个前端页面

1. `web/routes.py` 加页面路由（`response_class=HTMLResponse`）。
2. `templates/` 新建页面，继承 `base.html`。
3. `base.html` 导航加链接（注意 `request.url.path` 高亮）。
4. 数据用 `fetch` 拉，变更请求带 `X-CCCONVERT-CSRF`。
5. 第三方前端库**本地 vendored**（`web/static/`，并挂载），不要只依赖 CDN——用户可能断网/在墙内。

### 3.5 加服务端工具

1. `server_tools/` 实现并注册；`tools/handler.py` 负责循环。
2. 注意：一次客户端请求可能打多次上游，**每次都要计入用量**（实现用量统计后）。

## 4. 代码风格与约定

- 行宽 88，black + ruff；mypy `strict`（新增类型尽量写全）。
- 注释解释「为什么」，不要复述代码；涉及取舍时链接到 `决策记录.md`。
- 日志：默认 INFO 只留启动/错误/纠正；每请求的诊断放 DEBUG；**禁止打印 key 与请求正文**。
- 错误信息：对用户可见的用中文 + 上游原话，不要吞掉上游的 `error.message`。
- 提交：一句话说明做了什么；一个逻辑改动一个提交（便于 bisect）。

## 5. 发布

1. 更新版本号：`pyproject.toml`、`src/cc_convert/__init__.py`、`src/cc_convert/main.py`。
2. 更新 `CHANGELOG.md`（发布 workflow 会从中提取 release notes）。
3. `uv run pytest -q` 全绿。
4. 提交并推送；`git tag vX.Y.Z && git push origin vX.Y.Z` 触发 PyPI 发布 + GitHub Release。
5. Docker 镜像由 `docker.yml` 在 main/tag 上构建（需要仓库 secrets）。

## 6. 已知工具缺口（别以为是绿的就没问题）

- `mypy`、`black` 配置齐全但**不在 CI**；`ruff` 在 CI 里是 `continue-on-error`。
- 覆盖率目标（新代码 90%、总体 80%）写在 `AGENTS.md`，但**没有 CI 门槛**。
- `tests/test_integration.py` 有一个**无条件 skip**，即使设置了 `RUN_INTEGRATION_TESTS=1` 也不会跑。
- Docker 路径未验证（用户主线是 uv 源码运行）。
