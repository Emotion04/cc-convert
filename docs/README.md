# 文档索引

> 新接手的人（或 agent）请按「第一次接触」的顺序读。每份文档都只讲一件事，避免 CLAUDE.md 被塞成百科全书。

## 第一次接触（按顺序）

| 顺序 | 文档 | 读完你应该知道 |
|---|---|---|
| 1 | [`../CLAUDE.md`](../CLAUDE.md) | 项目是什么、怎么跑测试、几条硬约束 |
| 2 | [架构总览](架构总览.md) | 进程模型、请求从进到出的完整路径、模块职责 |
| 3 | [不变量与陷阱](不变量与陷阱.md) | **改代码前必读**：哪些规则不能破，破了会出现什么症状 |
| 4 | [开发指南](开发指南.md) | 环境、命令、常见改动配方、发布流程 |
| 5 | [测试指南](测试指南.md) | 测试沙箱怎么工作、怎么写流式/路由测试 |

## 按任务查

| 你要做的事 | 先读 |
|---|---|
| 改协议转换 / 流式 / 工具调用 | 架构总览 → 不变量与陷阱 → 测试指南 |
| 加一个 API 路由或面板页面 | 开发指南（配方）→ 架构总览（Manager 部分） |
| 动进程生命周期 / 端口 / 守护进程 | 不变量与陷阱 → 决策记录 ADR-005/006 |
| 想知道「为什么当初这么写」 | [决策记录](决策记录.md) |
| 做 Token 用量统计 | [用量统计设计](用量统计设计.md) → [实施计划](用量统计实施计划.md) |
| 接手未完成的工作 | [HANDOFF](HANDOFF.md) |
| 普通用户怎么用 | [使用规范](使用规范.md) |

## 文档维护规则

1. **决策记录只增不改**：推翻旧决定时追加新 ADR，并标注取代关系。
2. **不变量与陷阱**里的每一条都要能回答「违反了会发生什么」，否则删掉。
3. 架构总览里的图与模块表如果和代码不一致，以代码为准，并**当天修正文档**。
4. 不要在这里重复 CLAUDE.md 的短规则；深挖放本目录。
