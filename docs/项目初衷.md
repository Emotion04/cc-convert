# 项目初衷与使用方法

> 这份文档记录「为什么要做这个项目」「它解决谁的什么问题」「日常工作流长什么样」。
> 功能清单与技术细节见 [架构总览](架构总览.md) 与 [使用规范](使用规范.md)。

## 1. 它解决的错配

两条协议在生态里分布很不均衡：

- **OpenAI 协议**：几乎所有中转站、云厂商、本地推理框架都提供，密钥最容易拿到；
- **Anthropic 协议**：Claude Code 只认这一种。

于是存在一个错配：**手里只有 OpenAI 协议的 key，却想用 Claude Code 这个客户端。**

CC Convert 就是这座桥：在本地起一个进程，把 Claude Code 发出的 Anthropic 请求翻译成上游能懂的格式，再把响应翻译回来。对这个错配而言，代理层之外的一切都不需要改——上游不用换，客户端不用换。

反向（OpenAI 客户端 → Anthropic 上游）同样支持，但使用频率低，不是设计重心。

## 2. 为什么要有「按实例」这一层

一个人往往同时持有好几家的 key，用途也不同：便宜的跑日常、稳定的跑关键任务、大上下文的跑长文档。它们的上游地址、模型名、甚至协议格式都不一样。

所以项目的核心对象是**实例**：一个实例 = 一个上游地址 + 一个密钥 + 一个本地端口 + 一套模型映射。多开几个实例，就多几个可以并行的上游，互不干扰。

每个实例监听自己的本地端口，Claude Code 连接到哪个端口，就走哪个上游。

## 3. 日常使用流程

### 3.1 一次性准备

1. 打开面板（`ccconvert start` 或双击桌面版），创建实例：填上游地址、密钥、目标模型；
2. 在实例配置页的「Claude Code 配置」里填一个文件名（例如 `gguuai-claude.json`），保存时会自动写入 `~/.claude/` 下的最小配置。

### 3.2 每次启动

```bash
claude --settings gguuai-claude.json
```

窗口 1 用家 A、窗口 2 用家 B，各自带各自的 settings 文件，互不影响。因为配置文件里只写代理相关的几个字段，其余设置（权限、插件、状态栏）都从主 `settings.json` 继承。

### 3.3 配置里写了什么

生成的是**最小片段**，不是完整 settings：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:18402",
    "ANTHROPIC_AUTH_TOKEN": "local",
    "ANTHROPIC_MODEL": "deepseek-v4.1-flash-1017[1m]",
    "CLAUDE_CODE_MAX_CONTEXT_TOKENS": "1000000",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "970000"
  },
  "promptCacheTtl": "1h",
  "subagentPromptCacheTtl": "5m"
}
```

几个要点：

- `ANTHROPIC_AUTH_TOKEN` 默认是占位值 `local`：本地代理不校验客户端 token，真实密钥留在 cc-convert 的配置里，不落到 `~/.claude` 明文文件。若某个配置要直连上游（绕过代理），可勾选「写入上游真实密钥」。
- `ANTHROPIC_MODEL` 取自实例的目标模型；四个 tier 别名（`FABLE/OPUS/SONNET/HAIKU`）留空即继承它。
- 上下文窗口可手填、可点「1M」、可从上游探测；压缩阈值默认按 97% 自动算，也可手填。
- 两个缓存 TTL 只对 Claude 系列模型生效，其他上游会忽略，因此默认不写入。

## 4. 面板里能做什么

| 页面 | 用途 |
|---|---|
| 仪表板 | 实例总览、启停、重启、复制配置、删除 |
| 实例配置 | 上游参数 + Claude Code 配置联动（上下文/阈值/TTL/绑定文件） |
| Claude 配置 | 浏览 `~/.claude` 下所有配置文件，标注哪些已绑定到实例 |
| 用量统计 | Token 用量、缓存命中率、分实例/分模型对比 |
| 端口管理 / 日志 / API 测试 | 诊断工具 |

绑定关系由面板维护：一个配置文件同时只能绑一个实例（避免两个实例争抢同一文件），解绑时会清掉 cc-convert 写入的字段，文件里你自己的内容不受影响。

## 5. 不做什么

- **不记录请求正文**：只统计 token 数量；
- **不做隐式重试**：是否重试由 Claude Code 决定，代理不替客户端改变语义；
- **不替你管理密钥分发**：多机多人的密钥分发不在本项目范围内。
