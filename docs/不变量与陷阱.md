# 不变量与陷阱

> **改代码前先读这份。** 这里每一条都对应一次真实的故障或一个有意的取舍。
> 格式：规则 → 违反后的症状 → 怎么验证。
> 如果某条与代码不一致，以代码为准，并当天修正本文件。

---

## A. Token 与用量

### A1. Anthropic 的 `input_tokens` 不含缓存，OpenAI 的 `prompt_tokens` 含缓存

- **规则**：任何把 OpenAI usage 转成 Anthropic 的地方，必须调用
  `cc_convert.utils.tokens.anthropic_input_tokens(usage, fallback)`，
  它会减掉 `cached_tokens` 与 `cache_creation`。
- **症状**：直接透传 `prompt_tokens` → 缓存 token 被重复计费，Claude Code 显示的 input 翻倍；用量统计也会重复累加。
- **验证**：`tests/test_cache_usage.py`、`tests/test_router_comprehensive.py` 中的 usage 断言。

### A2. 缓存读取字段有三种写法

- `prompt_tokens_details.cached_tokens`（OpenAI/vLLM/SGLang）
- `prompt_cache_hit_tokens`（DeepSeek）
- `cache_read_input_tokens`（部分 vLLM）
- **规则**：统一走 `extract_cache_read_tokens()`，不要在业务代码里直接读某个键。
- **症状**：换一家上游，缓存率恒为 0。

### A3. 上游可以不返回 usage

- **规则**：流式请求尤其常见。拿不到就记「未上报」，**不要**按 0 或估算值记账。
- **症状**：面板数字比账单少，而且看不出来是少了。

## B. 协议转换（热路径）

### B1. `converter.py` / `streaming/handler.py` / `responses_converter.py` 是桥的核心

- **规则**：改动必须补测试；优先用已有字段，不要改事件顺序。
- **症状**：Claude Code 直接不可用（卡住、空回复、工具调用丢失）。
- **验证**：`tests/test_converter*.py`、`tests/test_router_comprehensive.py`、`tests/test_responses_api.py`。

### B2. 流式第一个 chunk 可能同时带内容和元数据

- **规则**：`message_start` 发出后**不要无条件 `continue`**，只有 `not chunk.get("choices")` 时才跳过。
- **症状**：首字丢失（历史 bug，已修）。

### B3. tool_result 是 `role: user`，但不是「新的一轮」

- **规则**：`turn` 策略里，判断轮次只看**真实用户输入**（`_is_tool_result_only`）。工具结果消息不算新轮。
- **症状**：多步工具调用中途，思考历史被清空 → 上游 400 或模型行为异常。

### B4. 孤儿 tool_call 需要补占位 tool 消息

- **规则**：assistant 消息带 `tool_calls` 时，后面必须有对应的 `tool` 消息；用 `_ensure_tool_results_for_tool_calls` 补齐，且不能重复补。
- **症状**：vLLM/SGLang 直接 400。

### B5. Responses 上游必须翻译请求体

- **规则**：`upstream_format == "responses"` 时，chat 形状的请求体必须经 `chat_body_to_responses_body()`；绝不能把 chat body 直接 POST 到 `/responses`。
- **症状**：上游 400（例如 `Unsupported parameter: repetition_penalty`），或返回 Responses 结构被当 chat 解析而 502。
- **验证**：`tests/test_upstream_responses.py`。

### B6. `/v1/responses` 在上下游同为 Responses 时直通

- **规则**：不要为了让代码统一而做「Responses → chat → Responses」往返，会丢字段（`instructions`、`tools` 形态、`store` 等）。
- **例外**：服务端 web search 需要 chat 循环，此时走转换路径。

### B7. 不要给上游塞「多余字段」

- 实测：某些中转对 `repetition_penalty: null`、`chat_template_kwargs` 直接 400。
- **规则**：新增参数前先确认目标协议是否支持；Responses 请求体只放 Responses 认识的字段。

## C. Manager / Worker 生命周期

### C1. 事件循环里禁止阻塞调用

- **规则**：`subprocess.run`、`proc.wait`、`time.sleep`、同步文件遍历都不能出现在 `async def` 里；用 `asyncio.to_thread`。
- **症状**：面板卡死、探测请求排队到超时、重启后几十秒打不开。
- **验证**：搜索 `async def` 内的裸 `subprocess.run`；实测并发请求延迟。

### C2. Windows 必须杀进程树

- **规则**：`taskkill /F /T /PID`，不是 `/F`。Worker 由启动器再 fork 一层，只杀父进程会留下占端口的子进程。
- **症状**：`WinError 10048`，实例启动失败，日志里健康检查一直 401。

### C3. Worker 必须跟随 Manager 退出

- **规则**：Worker 读 stdin 里的 `parent_pid`，后台线程每 2 s 检查；Manager 消失就退出。
- **症状**：`ccconvert stop -f` 后端点仍被占，下次启动失败。

### C4. 密钥只走 stdin

- **规则**：API key 不放进命令行参数、环境变量、日志；Manager → Worker 通过 stdin JSON。
- **例外**：Dashboard 的 `GET /api/instances/{id}/key` 会返回明文（本地便利，见 ADR-008）。
- **症状**：key 出现在进程列表或日志里。

### C5. `/_ccconvert/status` 是 Supervisor 的健康检查契约

- **规则**：只加字段，不改已有字段名/语义；鉴权用 `Bearer <internal_token>`；路径必须保持。
- **症状**：实例起不来，或起来就被判定失败。

### C6. 自启并发而不是串行

- **规则**：`startup_all` 用 `asyncio.gather`；每个实例端口/进程独立。
- **症状**：7 个实例顺序启动要 1–2 分钟，面板虽然开了但实例长时间不可用。

## D. 配置与路径

### D1. 路径只从 `runtime_paths` 拿

- **规则**：`get_config_dir` / `get_runtime_dir` / `get_log_dir` / `get_instance_dir`。禁止硬编码，禁止自己读环境变量。
- **症状**：`CCCONVERT_CONFIG_DIR` 失效；测试写进真实用户目录。
- **历史**：曾经有一个名字带空格的 `"CC Convert_CONFIG_DIR"`。

### D2. 配置文件是 Manager 的单一事实源

- **规则**：不要在 Manager 运行时手改 `config.toml`，会被内存中的 store 覆盖；改配置走 Dashboard/API。
- **症状**：改完重启又变回去，或出现两个不同步的配置。

### D3. schema 迁移必须幂等

- **规则**：`profile_store` 的 v1→v2 迁移、以及未来 `usage.db` 的 migration，都要能在已迁移的数据上重复执行。
- **症状**：重启后数据被重复迁移、字段被清空。

## E. 探测（thinking / format）

### E1. 探测失败不许写结论

- **规则**：只有 `ok=True` 的探测结果才能持久化/应用；超时、401、200/200 无信号都只提示。
- **症状**：一次网络抖动就把用户的策略改掉（曾经发生过）。
- **验证**：`tests/test_thinking_policy.py::TestProbeApply`。

### E2. 探测预算 20 s，两个请求并发

- **规则**：`probe_upstream` 共享一个 deadline；不要改回串行或按单请求计时。
- **症状**：慢中转（单次 15 s）永远探测失败。

### E3. 探测不许阻塞启动

- **规则**：Worker 的 `upstream` 探测放后台线程；格式探测最多一次请求超时即返回 chat。
- **症状**：端口迟迟不开放， Supervisor 健康检查超时，实例启动失败。

## F. 前端

### F1. 变更请求必须带 CSRF

- **规则**：`X-CCCONVERT-CSRF` 头，值来自 `<meta name="csrf-token">`；Manager 每次启动换新 token，页面过期返回 403。
- **症状**：保存/启动/探测全部 403。

### F2. 内部键与中文标签要成对出现

- **规则**：`auto/upstream/rules/turn/keep/drop` 这类键在 UI 上显示为「中文（key）」，探测结果、下拉、纠正横幅用同一套标签（`thinking_policy.POLICY_LABELS`）。
- **症状**：用户看到 `turn` 但下拉里没有这个选项，不知道怎么对应。

## G. 测试

### G1. 沙箱必须在模块级

- **规则**：`tests/conftest.py` 顶部设置 `CCCONVERT_CONFIG_DIR` / `CCCONVERT_RUNTIME_DIR`；不能写成 fixture（`daemon.py` 导入时就固化路径）。
- **症状**：测试覆盖真实配置（真实发生过）。

### G2. 不要真的执行 `taskkill`

- **规则**：涉及进程终止的测试必须 patch `subprocess.run` 并断言参数，或跳过 Windows 分支。
- **症状**：跑测试时杀掉用户机器上的进程。

### G3. 测试不得依赖真实网络

- **规则**：所有上游调用都 patch `httpx.AsyncClient` 或指向本地 stdlib server。
- **症状**：CI 随机失败、探测把用户真实 key 发出去。

## H. 日志与性能

### H1. 诊断日志默认 DEBUG

- **规则**：`[cache] prefix=...` 这类每请求一行的诊断只在 DEBUG；INFO 只留启动/错误/纠正。
- **症状**：日志文件暴涨、Windows 上磁盘 IO 拖慢请求。

### H2. 不在热路径做磁盘 IO

- **规则**：用量统计等后台工作走内存 + 定时批量落盘。
- **症状**：高并发下请求延迟抖动。
