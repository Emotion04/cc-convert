CC Convert API 文档

Anthropic ↔ OpenAI 双向协议转换代理，让 Claude Code / Anthropic SDK 运行在任意 OpenAI 兼容后端上。

简介

CC Convert 是一个本地运行的协议转换代理。Claude Code（只认识 Anthropic Messages 协议）把请求发给 CC Convert，CC Convert 转换为 OpenAI 格式转发给上游（vLLM、SGLang、云 API），再把响应转回 Anthropic 格式。

工作原理

Claude Code ──→ CC Convert Worker (本地端口) ──→ 上游 API (OpenAI / Responses)

一个 Manager（Dashboard + 生命周期管理）管理多个 Worker（每个实例一个独立进程、独立端口）。Supervisor 负责 Worker 的启停与健康检查。

三种运行模式

端点模式用途
/v1/messagesAnthropic 代理Claude Code 场景，Anthropic ↔ OpenAI 双向转换
/v1/chat/completionsOpenAI 透传OpenAI 客户端直连，零转换开销
/v1/responsesResponses 桥接OpenAI Responses SDK 对接只实现 chat/completions 的后端

快速开始

安装

bash
pip install cc-convert

启动 Manager

bash
ccconvert start

启动后 Dashboard 地址：http://127.0.0.1:<manager-port>（默认 18400 起，实际以启动输出为准）。在 Dashboard 里创建实例，配置上游地址与密钥，即可开始使用。

最小请求示例

python
import anthropic

client = anthropic.Anthropic(
    base_url="http://127.0.0.1:18401",  # 实例端口
    api_key="local",                    # 实例未配 key 时透传
)
resp = client.messages.create(
    model="my-model",
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好！"}],
)
print(resp.content[0].text)

配置文件

配置文件位于 ~/.ccconvert/config.toml（环境变量 CCCONVERT_CONFIG_DIR 可覆盖目录），首次运行自动创建。多实例配置由 Dashboard 管理，通常无需手改。

配合 Claude Code 使用

创建实例后，点击 Dashboard 卡片上的 复制配置，会得到环境变量或 settings.json 片段，填入 Claude Code 即可。

环境变量

bash
export ANTHROPIC_BASE_URL="http://127.0.0.1:18401"   # 实例端口，注意 http:// 前缀
export ANTHROPIC_AUTH_TOKEN="local"

settings.json

json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:18401",
    "ANTHROPIC_AUTH_TOKEN": "local",
    "ANTHROPIC_MODEL": "my-model",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "my-model"
  }
}
启动 Claude Code 时显示的是它自己配置的模型名；CC Convert 会按 target_model 覆盖后发给上游，实际生效模型以 Dashboard 实例的 目标模型 为准。

实例管理

每个实例是一个独立的代理进程，监听自己的端口，转换后转发到配置的上游。

实例字段

字段说明
name实例名称
port本地端口（自动分配，从 18401 起）
upstream_base_url上游 API 地址，须以 http:// 或 https:// 开头
upstream_api_key上游密钥（仅写入，永不回显）
target_model目标模型：覆盖所有请求的模型名；留空则透传
client_model 等Claude Code 模型注入（仅用于"复制配置"输出）
upstream_format上游协议格式（见"上游格式"节）
auto_startManager 启动时自动拉起该实例

模型映射

每个请求的模型名都会经 resolve_model() 三级解析：

  1. 精确匹配 model_mapping 规则
  2. 通配符匹配（fnmatch，如 *opus*）
  3. 回退 到实例的 target_model（空则透传原模型名）

最常用的做法是只设置 target_model：一旦填写，所有请求的模型名都会被覆盖为该值，发给上游。适合"一个实例对应一个后端模型"的场景。

上游格式

实例的 upstream_format 决定转发到上游的哪个端点：

值转发到适用后端
chat_completions{base}/chat/completionsvLLM、SGLang、绝大多数 OpenAI 兼容后端
responses{base}/responses实现 OpenAI Responses API 的后端
auto（默认）启动时探测先试 chat/completions，再试 responses，兜底 chat_completions

在 Dashboard 创建实例时可点"探测"按钮自动识别上游格式。

认证与密钥

向上游的认证

转发请求到上游时，认证头按以下优先级生成：

  1. 实例配置了 upstream_api_key → 用实例 key（Authorization: Bearer <key>）
  2. 未配置 → 透传客户端发来的 Authorization 头
  3. 都没有 → 透传客户端的 x-api-key 头

Claude Code 场景下，ANTHROPIC_AUTH_TOKEN=local 会被透传给上游。若上游是真实 API，需要把 local 换成上游认识的 token，或在实例里配置真实 key（推荐）。

Manager API 的安全

Manager 仅监听本机（Host 校验），写操作需要 X-CCCONVERT-CSRF 头（由页面自动附带）。密钥字段在 API 响应中永不回显，只暴露 key_configured 与 key_last4。

服务端 Web Search

CC Convert 内置服务端搜索（Tavily / 通晓），任何模型都能获得联网能力，无需客户端改造。在全局配置中填入搜索提供方的 API key，并选择 websearch_provider（tavily / tongxiao / both）。

Anthropic 端点通过 tools: [{type: "web_search_20250305", ...}] 触发；Responses 端点通过 web_search / web_search_preview 工具触发。搜索结果以 server_tool_use / web_search_tool_result 块返回。

故障排查

症状原因 / 解决
max_tokens is requiredAnthropic 请求缺 max_tokens，必填
上游 4xx / 5xx 原样透出上游返回的错误，检查实例 key / 模型名 / 上游状态
401 Unauthorized / Invalid token上游拒绝了认证：实例 key 无效，或透传的客户端 token 不被上游认可
"... cannot be parsed as a URL"ANTHROPIC_BASE_URL 缺 http:// 前缀
Model X does not exist模型名发到了不认识它的上游；检查 target_model 是否正确
端口被占Manager 自动找空闲端口并 evict 残留进程；到"端口管理"页查看

查看日志

每个实例的日志在 %LOCALAPPDATA%\ccconvert\instances\<id>\logs\（Windows），或 Dashboard 的"日志查看"页。Manager 日志用 ccconvert logs -f。

Base URL 与认证

所有代理 API 都挂在实例的本地端口上：http://127.0.0.1:<实例端口>/v1/...。实例端口在 Dashboard 卡片上显示，默认从 18401 起。

认证

请求头认证与"认证与密钥"节一致：实例配了 key 则代理用实例 key；否则透传客户端的 Authorization 或 x-api-key。Anthropic 客户端通常发送 x-api-key。

POST /v1/messages

创建一条消息。Anthropic Messages 格式，代理自动转换为 OpenAI chat/completions 请求发给上游，再把上游响应转回 Anthropic 格式。支持流式（stream: true）、工具调用、视觉输入与 thinking 推理块。

请求参数

参数类型必填说明
modelstring是模型名，会经 resolve_model() 映射后发给上游
messagesarray是{role, content}，content 可为字符串或内容块数组
max_tokensint是最大输出 token 数
systemstring / array否系统提示；自动去除 Claude Code billing header
toolsarray否工具定义；web_search_20250305 走服务端搜索
tool_choiceobject / string否auto / any / {type:"tool", name}
streamboolean否为 true 时返回 SSE 流
thinkingobject否{type:"enabled"/"adaptive", budget_tokens}，映射到上游 chat_template_kwargs
temperature / top_p / top_knumber否采样参数
stop_sequencesarray否停止序列，映射为上游 stop
repetition_penaltynumber否重复惩罚，透传

请求示例

bash
curl http://127.0.0.1:18401/v1/messages \
  -H "Content-Type: application/json" \
  -H "x-api-key: local" \
  -d '{
    "model": "my-model",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "用一句话介绍自己"}
    ]
  }'

响应示例

json
{
  "id": "chatcmpl-xxxx",
  "type": "message",
  "role": "assistant",
  "content": [
    {"type": "text", "text": "你好！我是 CC Convert 代理后的模型。"}
  ],
  "model": "my-model",
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 12,
    "output_tokens": 22,
    "cache_creation_input_tokens": null,
    "cache_read_input_tokens": null
  }
}

错误响应

json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens is required"
  }
}
流式模式返回 text/event-stream，事件序列：message_start → content_block_start → content_block_delta → content_block_stop → message_delta → message_stop。

POST /v1/chat/completions

原样代理 OpenAI 格式请求到上游，不做任何转换（避免 Anthropic↔OpenAI 转换开销）。请求体为任意 OpenAI chat/completions 格式；响应原样返回上游 JSON，状态码透传。流式时 SSE 逐块透传。

python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:18401/v1", api_key="local")
resp = client.chat.completions.create(
    model="my-model",
    messages=[{"role": "user", "content": "hi"}],
)
print(resp.choices[0].message.content)

POST /v1/responses

接收 OpenAI Responses 格式请求，转换为 chat/completions 发给只实现该协议的上游（vLLM、SGLang 等），再把上游响应转回 Responses 格式。让 OpenAI Responses SDK 客户端也能对接兼容后端。

请求字段

参数说明
model必填，经 resolve_model() 映射
input字符串或 item 数组（message / function_call / function_call_output / reasoning）
instructions系统指令，作为 system 消息
streambool，true 时返回 SSE 事件流
max_output_tokensint → OpenAI max_tokens
toolsfunction 工具转发；web_search 类走服务端搜索
reasoning{effort} → chat_template_kwargs.reasoning_effort
python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:18401/v1", api_key="local")
resp = client.responses.create(
    model="my-model",
    input="你好",
)
print(resp.output_text)

GET /v1/models

列出上游可用的模型。直接代理转发到 {上游 base_url}/models，响应原样返回（OpenAI list 结构），不做转换。

bash
curl http://127.0.0.1:18401/v1/models -H "x-api-key: local"
json
{
  "object": "list",
  "data": [
    {"id": "my-model", "object": "model", "created": 1720000000, "owned_by": "vllm"}
  ]
}

POST /v1/messages/count_tokens

本地估算 token 数（用 tiktoken 的 cl100k_base 近似 Claude 模型）。请求体：{messages, model, system, tools}，返回 {"input_tokens": <int>}。

GET /health

健康检查，返回 {"status": "healthy"}。Docker 等场景用它判断服务存活。

Manager API · 实例 CRUD

以下 API 挂在 Manager 端口（Dashboard 同源），用于编程式管理实例。所有写操作需要 X-CCCONVERT-CSRF 头（从任意页面 meta 标签获取）。

GET /api/instances

列出全部实例（含实时状态）。密钥字段永不返回，只暴露 key_configured / key_last4。

POST /api/instances

创建实例。必填：name、upstream_base_url（须带协议头）、upstream_api_key。可选：port（缺省自动分配）、target_model、client_model 系列、upstream_format、auto_start。校验失败返回 422。

GET /api/instances/{id}

单个实例详情。

PATCH /api/instances/{id}

部分更新。修改 target_model 等运行相关字段会触发 Worker 滚动重启（失败自动回滚）；仅改 name / auto_start / client_* 不重启。发送 clear_upstream_api_key: true 可清空密钥。

DELETE /api/instances/{id}

删除实例，仅限已停止状态（运行中返回 409）。
